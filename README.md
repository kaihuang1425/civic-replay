# Civic Replay — 公共服務情境預演

> 在公共服務、政策或事件真正上線之前，先讓不同現實條件的居民「走一次」完整流程，
> 看看誰會卡在哪一步、為什麼卡住，以及修改服務之後這些人是否真的被接住。

## 問題與解法摘要

公共服務、補助申請或災害應變流程，設計時通常以「一般居民」為預設對象測試：
會用 LINE、看得懂公文用詞、有交通工具、能自己上網申請。但獨居長者、新住民、
行動不便者、沒有智慧型手機的居民、需要家人代辦的居民，往往在正式上線後才發現
某個步驟卡死了他們——而這時候補救的成本已經很高。

**Civic Replay** 讓公共服務設計者用自然語言描述一項服務或情境，由 AI 產生一份
可編輯的「沙盤」（服務流程 + 資格規則 + 六種代表性居民），接著讓每一位居民逐步
「預演」整個流程：能不能收到通知、看不看得懂用詞、能不能親自到場、能不能完成
身分驗證⋯⋯每一步都會被判定為 **PASS（可自行完成）／NEED HELP（需要協助）／
BLOCKED（完全卡住）**，並附上判定依據。設計者可以針對卡住的原因加入電話備援、
志工協助、多語言說明、家人代辦等介入措施，重新預演一次，直接比較「這個修改救到
了誰、還有誰沒被接住」。

判定分成兩層：能用明確條件判斷的（例如「只靠 LINE 通知、居民沒有 LINE」）交給
**規則引擎**，確定且可重現；牽涉語意理解的判斷（例如「這段公文用詞居民看不看得
懂」）才交給 **AI**，且所有 AI 判定的結果都會標記「仍需真人／地方單位驗證」，
不會被當成最終答案。

## 目標使用者與價值

- **目標使用者**：地方政府 / 中央機關的公共服務設計者、政策幕僚、災害應變規劃
  人員——任何需要在服務上線前檢查「這個流程會不會漏掉哪些居民」的人。
- **居民面臨的具體問題**：服務流程假設居民有智慧型手機、看得懂行政用語、能自行
  前往現場、能自己完成身分驗證；不符合這些假設的居民往往要等到申請失敗、錯過
  補助或錯過避難通知才會被發現。
- **使用價值**：把「這個流程對弱勢居民是否可行」從上線後的客訴，提前變成上線前
  可以重複測試、比較修改前後差異的動作。目前的判定是 AI 模擬結果，**仍需真人或
  地方單位實地驗證**，不能取代真實測試。

## 目前可操作的功能

以下功能皆已在本機以自動化測試（61 個測試，`npm test` 全數通過）與手動走查驗證：

- **自然語言 → 沙盤生成**：輸入一段情境描述（或點選範本），AI 產生服務流程
  （每步驟含名稱、意圖、對應管道）、服務管道、資格規則、備援選項、6 位代表性
  居民，以及 AI 擷取的重點（主題、服務目標、核心限制、主要管道）。
- **生成設定可編輯並重新生成**：情境類型、服務管道、資格規則、備援選項、居民
  人數皆可編輯，按「重新生成」後會保留你手動修改過、且未被新設定覆蓋的欄位。
- **5 個快速套用範本**：災害救助、育兒補助、疫苗預約、租屋補貼，以及固定驗證
  情境「豪雨／淹水」。
- **預演每位居民**：規則引擎 + AI 引擎逐步判定每位居民在每個步驟的結果
  （PASS / NEED HELP / BLOCKED），附上判定依據、判定者（規則或 AI）、狀態變化，
  並整理出卡住的步驟與系統性原因（root cause）。
- **介入措施與 Replay Diff**：可加入電話備援、志工 / 里長人工確認、多語言說明、
  家人代辦協助（各自對應不同的卡關原因），重新預演後與先前結果比較，顯示
  Reached / Able to act / Unresolved 三項統計的前後變化，以及「這個介入措施救到
  了誰」的逐項說明。
- **沙盤預覽面板**：不執行完整預演，先用規則引擎做一次快速檢查，列出風險
  Top 5、建議介入措施（可一鍵加入）、預估結果分布（標示為 AI 估算，非正式預演
  結果）。
- **儲存 / 我的沙盤 / 匯出**：沙盤可儲存、從清單載入、匯出成 JSON。
- **降級模式**：沒有可用的 AI（Ollama 離線或未設定）時，生成會退回範本內容，
  預演的語意判斷步驟會標記為「AI 未啟用」並要求人工確認，介面上有「AI：離線
  （降級模式）」提示——整個流程不會因為沒有 AI 而中斷。

### 完整示範情境：豪雨／淹水

目前只有 **豪雨／淹水（`heavy-rain-flooding`）** 這個情境有完整手工建置並驗證過
的沙盤內容（固定的 6 步驟流程、6 位居民、每一步的判定邏輯都經過測試）。用這個
範本可以走完「生成 → 預演 → 看到 4 位居民卡住 → 加入介入措施 → 再次預演 →
比較差異」的完整流程，這也是 `docs/DEMO_SCRIPT.md` 錄影腳本使用的情境。

其他 4 個範本（災害救助、育兒補助、疫苗預約、租屋補貼）可以正常生成沙盤與執行
預演，但：

- 有可用的 Ollama 時，AI 會依範本描述客製化生成服務流程（僅在開發期間對「育兒
  補助」手動驗證過一次，見 `docs/ARCHITECTURE.md` 的記錄）；
- 沒有 Ollama（降級模式）時，這 4 個範本只會退回一份**通用的 6 步驟骨架**
  （知道服務 → 確認資格 → 選擇管道 → 準備文件 → 身分驗證 → 取得結果），套用
  範本卡片裡設定的管道 / 資格規則文字，內容豐富度不如豪雨情境。

輸入框可以自由打字，但**不代表系統理解任意情境**——自由輸入的文字只會被拿去
比對關鍵字（決定情境類型）與做文字相似度比對（決定退回哪個範本），不是真正的
語意理解；要看到穩定、完整驗證過的結果，請使用「豪雨／淹水」範本。

## 操作流程

1. **設定情境**：在頂部輸入框描述一項公共服務或情境，或點選下方範本卡片
   （例如「豪雨／淹水」）快速帶入預設描述與設定 → 按「✨ 生成沙盤」。
2. **檢視並調整沙盤**：中間欄看服務流程（流程圖模式 / 旅程模式）與 6 位居民卡片
   ；左側欄可編輯生成設定並「↻ 重新生成」；右側欄看 AI 擷取重點、風險 Top 5、
   建議介入措施、預估結果分布。
3. **執行預演**：按「▶ 執行預演」，逐一查看每位居民的狀態（🟢 PASS / 🟠 NEED
   HELP / 🔴 BLOCKED），點開任一位居民可看到逐步判定原因、證據、卡住的步驟與
   root cause。
4. **加入介入措施**：從右側「建議介入措施」一鍵加入，或視需要移除。
5. **重新預演並比較**：再次「執行預演」後，按「⇄ 比較前後（Replay Diff）」，
   查看 Reached / Able to act / Unresolved 的前後變化，以及每個介入措施救到了
   哪些居民。
6. **儲存 / 匯出**：可隨時「儲存」目前沙盤，之後從「我的沙盤」載入，或「匯出
   沙盤」為 JSON 檔。

尚未完成 / 目前不支援的部分：

- 沒有「一鍵匯入外部服務定義」——只能用自然語言描述或既有範本，不能貼上既有
  政府網站或 PDF 表單讓系統自動解析。
- 沒有帳號、多人協作或分享連結（規格文件中已明確列為 non-goal）。
- 居民人數雖然設定上限是 12 人，超過 6 人的部分是把 6 種原型循環複製（附加
  編號），**不是**真的生成新的、獨立的居民樣態；不是自由生成任意人數的獨特角色。
- 介面上「AI 估算」的預估結果分布，實際上是規則引擎的快速預估，**不是**呼叫
  AI 產生的——完整、可信的結果請以「執行預演」為準（細節見
  `docs/ARCHITECTURE.md`）。

## 技術組成

npm workspace monorepo：

| 套件 | 內容 |
| --- | --- |
| `shared/` | zod schema + TypeScript 型別、介入措施 catalog（前後端共用） |
| `server/` | Express API、JSON 檔持久化（無資料庫）、規則引擎 + AI 引擎、AI provider 抽象層 |
| `web/` | Vite + React 主控台（單畫面三欄式介面，Zustand 狀態管理、TanStack Query） |
| `data/seeds/` | 6 個固定居民、5 個情境範本、完整驗證情境 `heavy-rain-flooding` |

- **規則引擎**先判斷能明確決定的條件（管道 / 裝置限制、移動能力、身分代辦、
  典型居民直接 PASS）；**AI 引擎**只處理規則判不了的語意理解問題（例如公文用詞
  難不難懂），且所有 AI 判定一律標記 `requiresHumanValidation: true`。
- **AI provider** 目前只註冊了一個：本機 [Ollama](https://ollama.com)（模型
  `gpt-oss:120b-cloud`）。程式以一個 provider-agnostic 介面呼叫 AI，之後要換成
  OpenAI API 只需新增一個 provider 實作，不用動引擎程式碼（尚未實作，僅預留
  介面）。

完整架構、資料流與程式路徑見 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 快速啟動

```bash
git clone <此儲存庫>
cd civic-replay
cp .env.example .env        # 視需要調整 OLLAMA_HOST / OLLAMA_MODEL / AI_PROVIDER
npm install
npm run dev                 # server :8787、web :5173
```

沒有 Ollama 也能跑完整流程：生成會退回範本內容，預演的語意判斷步驟會標記為
需人工確認（見上方「降級模式」）。完整安裝、環境變數、示範步驟與常見問題見
[`docs/SETUP.md`](docs/SETUP.md)。

```bash
npm test          # shared / server / web 全部測試（目前 61 個測試皆通過）
npm run typecheck
npm run build
```

## 已知限制

- 判定結果是 AI 與規則的**模擬**，不是實際申請系統或真實居民資料，上線前仍需
  真人 / 地方單位驗證。
- 只有「豪雨／淹水」情境有完整驗證過的沙盤內容；其他範本在沒有 AI 時只會得到
  通用骨架（見上方「完整示範情境」）。
- 居民樣態固定為 6 種原型（可循環複製湊人數，但不是獨立生成的新樣態），不是
  任意人數的居民生成器。
- 自由輸入的情境描述不會被完整理解，只用於關鍵字比對與生成 AI 提示；沒有解析
  PDF 或既有政府網站的能力。
- 單一伺服器 + JSON 檔持久化，沒有資料庫、帳號系統、多人協作或分享連結，不適合
  正式營運環境。
- 沒有串接任何政府單位的真實系統或真實居民資料。
- AI provider 目前只實作 Ollama 一種；健康檢查會回報 `gpt-oss:120b-cloud` 顯示
  「未 pull」，這是因為它是 Ollama 的雲端推論模型別名，非 `/api/tags` 可列出的
  本機模型，屬於預期行為（詳見 `docs/SETUP.md`）。
