# 展示影片腳本（≤ 120 秒）

**狀態：腳本，尚未錄製、尚未上傳影片。** 請勿在繳交文件中標示影片已完成，直到
實際錄製並上傳為止（見 `docs/SUBMISSION.md`）。

腳本內容對應目前 repo 實際可操作的功能，時間包含畫面操作與必要的等待時間。
建議錄製環境：**沒有連接 Ollama**（示範模式），理由是：(1) 行為完全可預期、
數字固定，方便對稿；(2) 不用等待 LLM 回應時間，全程可以控制在 2 分鐘內；
(3) 剛好可以展示「沒有 AI 也能跑完整流程」這個實際存在的降級能力。若團隊改用
真實 Ollama 錄製，AI 判定的等待時間（可能數十秒）**務必**在剪輯時跳剪，不可
不剪就超時。

前置作業（錄影開始前，不算在 120 秒內）：`npm run dev` 已啟動、瀏覽器已開啟
`http://localhost:5173`、畫面乾淨（尚未生成任何沙盤）、`.env` 未指向可用的
Ollama（或直接不建立 `.env`，讓系統走預設降級模式）。

總長：約 **120 秒**（可依錄製節奏在 0:45–0:55、0:12–0:28 兩段等待畫面壓縮，
保留緩衝時間）。

## 若團隊決定加錄「其他範本」或「AI 在線」片段

腳本本身已可在 120 秒內完整交代問題、預演、卡關原因、介入措施與比較結果，
**不建議**額外加入其他範本或即時 AI 判定片段，理由：

- 其他 4 個範本（災害救助、育兒補助、疫苗預約、租屋補貼）目前沒有 Ollama 時
  只會顯示通用骨架，畫面上的服務步驟不如豪雨情境有針對性，容易讓評審誤以為
  所有情境都經過同等打磨（實際上只有豪雨情境經過完整手工建置與測試）。
- 真實 Ollama 判定每個語意步驟可能需要數十秒（見 `docs/SETUP.md` 的手動驗證
  紀錄，全流程約 48 秒），必須大量跳剪才塞得進 2 分鐘，容易讓時間軸與旁白對不
  齊。

如果團隊仍想展示「AI 在線」的差異，建議另外錄一段**不計入正式繳交影片**的
補充片段，畫面重點放在「AI 判定的原因文字比規則引擎的模板文字更具體」，並在
旁白明確說明這段是額外補充。
