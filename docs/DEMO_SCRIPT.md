# 兩分鐘展示腳本

本文件是錄影腳本，目前尚未收到影片連結。旁白以固定豪雨範本為例，說明收不到通知的人如何在服務調整後繼續辦事。

## 錄影前

依[安裝與執行](SETUP.md)啟動備援示範模式，確認畫面顯示 AI 離線，並先試走一次。固定範本便於比較，不要將這段畫面說成即時 AI 生成。

錄影前準備好瀏覽器、情境範本與麥克風。等待畫面可剪短；下列時間是剪輯安排，實際成片需確認不超過兩分鐘。

## 畫面與旁白

| 時間 | 畫面 | 旁白 |
| --- | --- | --- |
| 0:00–0:20 | 首頁，選「豪雨／淹水」，生成沙盤 | 「Civic Replay 是公共服務情境預演工具。政策上線前，我們先模擬不同居民的辦事過程，找出問題，再比較修改前後的結果。這次用豪雨範本示範。」 |
| 0:20–0:40 | 顯示流程與居民條件，執行預演 | 「警報只用 LINE 通知，但有些居民沒有使用 LINE，也有人無法自行移動。我們把這些條件放進流程，看看居民會在哪一步卡住。」 |
| 0:40–1:05 | 展開獨居長者的通知步驟 | 「六位居民中，有四位無法完成。這位居民在第一步就收不到通知，原因是她沒有使用 LINE，服務也沒有其他通知方式。」 |
| 1:05–1:35 | 加入電話備援、志工協助、多語言說明；再預演 | 「現在加入電話通知、志工協助和多語言說明，保持其他條件不變，再跑一次。無法完成的人從四位降到一位，其中三位改為需要協助。」 |
| 1:35–1:55 | 比較前後，顯示仍卡住的代辦居民與團隊名稱 | 「還有一位需要家人代辦，這次的修改沒有解決她的問題。預演讓我們看見哪些修改有幫助，也留下還要處理的問題，供地方單位進一步確認。」 |

保留最後五秒緩衝，不必唸出所有統計欄位。重點是卡關原因、修改內容與仍未解決的問題。

## 數字與用語

固定備援範本加入上述三項措施後，`Unresolved` 為 4 → 1，`Able to act` 仍為 1 → 1，`Reached` 為 3 → 5。需要協助不等於已自行完成；`Reached` 也不是申請成功人數。

介面名稱目前是「電話 fallback」、「志工 / 里長人工確認」、「多語言說明」。錄影時先確認這三項都已加入，不要誤加家人代辦措施而改變示範結果。

若要展示模型判讀，可另外錄下 AI 連線成功時的片段，清楚標示與備援示範的差別。不要把離線結果配上「AI 正在判斷」的旁白。

## 完成後

確認聲音、畫面與總長度，補上 YouTube 連結到[參賽資料](SUBMISSION.md)，並在未登入的瀏覽器中試播。影片可見性依繳交要求設定。
